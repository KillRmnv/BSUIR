# AGENTS.MD — TIISPIS/lab1

## What this project is

Labs 1-3 for TIISPIS (Технологии интеллектуальной обработки информации в специальных информационных системах). OSTIS knowledge base modelling the **Science** domain using SCs-code (`.scs` files). No build system, no runtime — the files are declarative ontology definitions loaded by sc-machine (>= 0.9.0).

## Directory layout

```
lab1/
  science_domain.scs      ← main ontology: classes, relations, instances, triples
  kb/extra/section_subject_domain_science/   ← split-out KB (concepts, relations, instances, classification)
  docs/                   ← reference material (SCs-code syntax cheat-sheet)
  templates/              ← reusable .scs templates (class, instance, nrel, etc.)
  non_subject_domain_concepts/wit/  ← NIKA wit.ai integration (concept_wit_entity, nrel_wit_ai_idtf, etc.)
  section_subject_domain_of_messages/  ← NIKA default message classes
  pattern/scs/            ← SCs templates for rules, phrases, messages
  pattern/science/        ← .gwf templates for rules and phrases
  test/                   ← wit.ai export data
```

## NIKA classification rules (labs 2-3)

### Message classes
- Use `<- sc_node_class;` (NOT `<- concept_intent_possible_class;`)
- Must have `=> nrel_wit_ai_idtf: [intent_name];` matching wit.ai exactly
- Add new message classes to `concept_intent_possible_class` via `->` (not `<-`)
- **Do NOT create `concept_answer_message`** — answers are generated by rules, not classified by wit.ai

### Entity classes
- Entity class: `<- concept_entity_possible_class;` + `=> nrel_wit_ai_idtf: [rrel_entity];`
- Role: `<- sc_node_role_relation;` + `=> nrel_wit_ai_idtf: [rrel_entity];`
- Connect entity to subject domain: `-> concept_science;`
- Define role via `=> nrel_entity_possible_role: ..role_name;;`

### Rules (SCs format)
- Use `@if` / `@then` pattern with `[* ... *];;`
- Rule class: `<- concept_answer_on_standard_message_rule;` + priority
- Reply: `_message _=> nrel_reply:: _reply_message;;`
- Phrase pattern: `=> nrel_answer_pattern: { rrel_1: phrase_class };`
- Connect: `<- rrel_main_key_sc_element: (@if => @then) (* <- nrel_implication;; *);;`

### Phrases
- Simple: `<= nrel_inclusion: concept_phrase; -> [текст] (* <- lang_ru;; *);;`
- Template: `@pattern = [* ... *];;` + `=> nrel_phrase_template: @pattern;;`

## SCs-code conventions

- Sentences end with `;;` (double semicolon)
- Internal attribute sentences use `(* ... *)` blocks (level 5)
- Language tagging: `(* <- lang_ru;; *)` / `(* <- lang_en;; *)`
- Relation domain declarations: `=> nrel_first_domain: ...; => nrel_second_domain: ...`
- Hierarchy via `<= nrel_inclusion: <parent_class>;`
- Templates in `templates/` show the standard patterns

## Rules

- **Work only inside this `lab1/` directory.** Never edit files in other TIISPIS subdirectories.
- **No build or test step** — `.scs` files are loaded by sc-machine at runtime.
- Keep Russian/English bilingual identifiers (`lang_ru` + `lang_en`) for all user-facing concepts.
- When adding new concepts/instances, follow the exact pattern in `science_domain.scs`: class declaration → `nrel_main_idtf` in both languages → `nrel_note` in Russian.
- When adding relations, always declare `nrel_first_domain` and `nrel_second_domain`.
- Don't commit generated files or build artifacts.
