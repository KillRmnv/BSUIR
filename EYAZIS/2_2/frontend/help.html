Classification Theory

Text Preprocessing
Body extraction — <script>, <style>, <noscript> blocks are removed along with their content, then only <body> is taken (if absent — the whole document), remaining tags are stripped, HTML entities are decoded. Implementation: lang_text.extract_body_text.
Diacritics-aware preprocessing — lowercasing, digit/punctuation removal, but French letters are preserved: é è ê ë à â ç î ï ô ù û ÿ œ æ. This is critical: the regular search clean_text keeps only a–z and "blinds" French. Implementation: lang_text.preprocess_for_lang.
Chunking — training corpus is split into ~2000-char fragments at sentence boundaries: instead of 2 giant strings the classifier gets dozens of examples. Implementation: lang_text.chunk_text.
N-gram Method (Cavnar & Trenkle)
Character n-grams (1–5 chars) are extracted from the training corpus, top-300 by frequency form a language profile (backend/lang_profiles/ngram_en.json, ngram_fr.json). The same profile is built for the target document; distance is out-of-place: sum of rank differences, with a penalty of 300 for missing n-grams. The language with the smallest distance wins. Implementation: lang_ngram.py.
distance = Σ |rank_doc(g) − rank_lang(g)|, penalty = K if n-gram missing
Alphabet Method
Reference character sets: English — a–z, French — a–z plus diacritics (é è ê ë à â ç î ï ô ù û œ æ). The ratio of specific characters in the input text is computed; when none are found, the decision falls back to base Latin letter frequency and marker words (le/la/les/des vs the/and/of). The final score is weighted; the threshold is tuned on the training corpus and stored in backend/lang_profiles/alphabet.json. Implementation: lang_alphabet.py.
Neural Method (Logistic Regression)
Logistic regression on character TF-IDF features (1–5 grams, max_features=5000). Trained on corpus chunks, validated with 80/20 holdout. Outputs probabilities P(EN) and P(FR). Advantages: trains in seconds on CPU, deterministic, provides probabilities out of the box, small model. Implementation: lang_detect.train / classify_text / classify_html, model: backend/lang_profiles/ml_model.pkl.
P(fr|x) = 1 / (1 + exp(−(w·x + b)))
Classification Metrics
Accuracy — fraction of correctly classified test documents. Ground truth comes from test_html/manifest.csv. Confusion matrix — 2×2 table showing how many English/French documents were classified as each. Timing — average classification time per document in milliseconds.
Accuracy = correct / total

Search Theory

TF-IDF
Word weight: frequency in the document (TF) × rarity across the collection (IDF). Document vectors are built in document_processor.vectorize_text_with_dim.
TF-IDF(t,d) = TF(t,d) × IDF(t)
Cosine Similarity
Measures how similar a query and a document are: the cosine of the angle between their vectors. Search uses the pgvector operator <=> in database_manager.search_documents.
similarity = (A·B) / (||A|| × ||B||)
pgvector
PostgreSQL extension for storing vector embeddings (dimension 5000 here) and nearest-neighbor search. Tables: documents, search_logs.
Vocabulary & IDF
Word → vector index mapping and IDF weights are held in memory (VOCAB, IDF) and in tables vocabulary, idf_values; expanded incrementally on upload (expand_vocabulary).
Stemming & Stop Words
Porter stemmer reduces words to their root; English stop words are removed before vectorization (document_processor.clean_text). Note: English search only — not used for classification.
Precision / Recall / F-Score
Search quality metrics on the Metrics tab: fraction of relevant among retrieved / fraction of retrieved among relevant / their harmonic mean. Implementation: evaluator.py.
F1 = 2·P·R / (P + R)
Snippet & Auto-summary
Snippet — fragment around the first match with <mark> highlighting (highlight_snippet). Auto-summary — top-3 sentences by TF-IDF weight, computed at index time (generate_summary).
Migrations & File Watcher
DB schema is applied via numbered SQL files from backend/migrations/ through migrate.py (not Alembic). File watcher — a separate CLI client that sends file create/modify/delete events to /api/watch-event.

Summarization Theory

Extractive Summarization
The summary is built by selecting the most important sentences from the original text without rewriting or paraphrasing. Both methods implemented in this system are extractive: they rank sentences and pick the top-N in original document order.
Sentence Extraction (TF-IDF + Positional)
Each sentence receives a score based on the TF-IDF weights of its terms, adjusted by positional heuristics:
  • Term weight: augmented TF: 0.5 + 0.5 × tf(t,D) / tf_max(D) — rewards frequent terms while capping influence of very common words.
  • Document position (Posd): 1 − chars_before / total_chars — earlier sentences are weighted higher.
  • Paragraph position (Posp): 1 − chars_before_in_para / para_len — first sentence of each paragraph is preferred.
Final score: Score(Si) = Σ tf(t,Si) × w(t,D) × Posd(Si) × Posp(Si)
Score(Si) = Σ [tf(t,Si) × (0.5 + 0.5·tf(t,D)/tf_max(D))] × Posd(Si) × Posp(Si)
TextRank (Graph-based)
Sentences are vertices in a graph; edges represent cosine similarity between their TF-IDF vectors. PageRank is run on this graph to determine the most "central" sentences.
  • Similarity: cosine similarity between normalized TF-IDF sentence vectors.
  • PageRank: iterative algorithm with damping factor d = 0.85, convergence tolerance 1e-6, max 50 iterations.
  • Sentences with the highest PageRank score are the most connected to other important sentences.
PR(i) = (1−d)/N + d × Σ [PR(j) / OutDeg(j)]
Compression Ratio
The ratio of the summary length to the original document length, expressed as a percentage. A lower ratio means a more concise summary. Typical extractive summaries achieve 15–30% compression.
compression = len(summary) / len(original) × 100%
Keywords Extraction
Keywords are extracted from the document by TF-IDF weight: each term's TF in the document is multiplied by its IDF (within the document context). The top-K terms by weight are returned as keywords. Implementation: summary_engine._extract_keywords_from_text.

Translation Theory

Word-by-Word Translation
Each English word is looked up in a translation dictionary and replaced with its French equivalent. The system performs direct translation without reordering or morphological adjustment. Dictionary entries include source POS (NLTK), target POS, and frequency. Implementation: translator.translation_engine.translate_text.
Translation Coverage
Coverage = (translated words / total words) × 100%. Untranslated words are kept in English. Coverage depends on dictionary completeness: bootstrapping loads ~800+ common word pairs. Implementation: translator.translation_engine.translate_text (stats.coverage).
coverage = (translated / total) × 100%
POS Tagging (EN/FR)
English: NLTK averaged perceptron tagger (averaged_perceptron_tagger_eng). French: NLTK perceptron tagger (perceptron_tagger_fr). Both fall back to a rule-based heuristic when the model is unavailable. POS tags are used for accurate dictionary lookup and syntax parsing. Implementation: translator.pos_tagger.
Syntax Parsing
Constituency parse trees built with NLTK RegexpParser. English grammar: NP (determiner + adjective + noun), VP (verb + NP/PP), PP (preposition + NP). French grammar: GN (det + adj + NC/NPP), GP (verbe + GN/PP), GP (préposition + GN). Parse trees reveal sentence structure for future morphological or reordering improvements. Implementation: translator.syntax_parser.
Dictionary Bootstrap
Initial dictionary built from two sources: (1) 800+ hand-curated common word pairs (articles, prepositions, pronouns, verbs, nouns, adjectives, adverbs, CS terminology); (2) frequency-aligned extraction from parallel EN/FR corpora in the project. More pairs can be added via the Dictionary tab or API. Implementation: translator.dict_builder.bootstrap_dictionary.
Frequency List
Counts word occurrences in input text, ordered by frequency descending. Each word is enriched with its POS tag, French translation from the dictionary, and frequency count. Useful for identifying key terminology before full translation. Implementation: translator.translation_engine.get_frequency_list.

System Overview

Search

Vector search across the corpus. Results are ranked by similarity, matches are highlighted.

Upload

Add documents: paste text or upload a file (.txt/.md/.pdf/.docx/.html/.rtf/.csv/.log).

Documents

Browse all indexed documents, delete unwanted ones.

Metrics

Evaluate search quality: precision/recall/F-score for queries with known relevant document IDs.

Classification

Train models, classify a single HTML/text file or run the full test corpus with accuracy, confusion matrix, and timing; CSV export and print for reports.

Summarize

Generate extractive summaries using Sentence Extraction or TextRank. Choose method, sentence count, view highlighted sentences in original text.

Translate

Word-by-word EN→FR translation with POS tagging, syntax tree visualization, and dictionary management. View word frequency lists and translation coverage.
