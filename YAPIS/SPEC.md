## 0.5. Обоснование предметно-ориентированного подхода

ImgLang — предметно-ориентированный язык (DSL) для обработки изображений. Его цель — сократить разрыв между задачей («инвертировать красные пиксели») и кодом, который её описывает.

### 0.5.1. Синтаксический сахар для предметной области

Повторяющиеся паттерны обработки изображений свёрнуты в лаконичные конструкции, отсутствующие в универсальных языках:

| Доменная концепция | В универсальном языке (Python/C++) | В ImgLang |
| :--- | :--- | :--- |
| Загрузить изображение | `cv2.imread("f.jpg")` — импорт, BGR-порядок, numpy-массив | `load("f.jpg")` |
| Пройти по всем пикселям с фильтром | `for i in range(h): for j in range(w): if is_red(img[i,j]): ...` | `src -> (isRed()) .invert()` |
| Классификация по яркости | `if is_dark: c=0 else c=255` с циклом | `src -> (isDark()) .color(0) : (!(isDark())) .color(255)` |
| Применить оператор Собеля | Свёртка с двумя ядрами, магнитуда — ~20 строк | `src -> () .sobel() ::save("edges.jpg")` |

**Ключевые сокращения:**

1. **Потоковый оператор `->`** — заменяет вложенные циклы по пикселям + условный оператор одной строкой.
2. **Неявное преобразование `int → color`** — `color c = 255` избавляет от конструктора `new Color(255,255,255)`.
3. **Литералы цвета без `new`** — `255`, `(0, 0, 255)`, `{R:0, G:0, B:255}`, `color(0, 0, 255)` — самостоятельные выражения (см. нетерминал `colorLiteral` в п. 1.1).
4. **Индексация `img[x, y]`** — естественное для графики lvalue/rvalue.
5. **Предикаты в потоке** — `isRed()`, `isBright()` и выражения над `R`, `G`, `B`, `x`, `y` без явного объявления текущего пикселя.
6. **Мульти-ветвление `:` / `::`** — классификация пикселей без лесенок `if-else` и временных буферов.

### 0.5.2. Лёгкость восприятия для специалистов

Язык ориентирован на пользователей, знакомых с обработкой изображений, но не желающих изучать универсальный язык со всем его арсеналом:

1. **Терминология предметной области.** Имена встроенных функций (`load`, `save`, `grayscale`, `blur`, `sobel`, `invert`, `resize`, `crop`, `rotate`) и предикатов (`isRed`, `isBright`, `isContour`) взяты из лексикона фотографов и дизайнеров — они не требуют перевода из терминов машинного обучения или компьютерного зрения.

2. **Декларативный стиль потока.** `img -> (isRed()) .invert() .save("out.jpg")` читается как предложение: *«Взять изображение → (где красное) → инвертировать → сохранить»*. Никаких вложенных циклов, индексов и временных переменных — только логика обработки.

3. **Минимум теории.** Язык не требует знания классов, наследования, обобщённых типов, указателей, исключений или перегрузки операторов. Типы ограничены доменом (`image`, `pixel`, `color`) плюс минимальный «склей» (`int`, `float`, `bool`, `string`).

4. **Предикаты как естественные вопросы.** Вместо `if brightness(pixel) > threshold` — просто `(isBright())`. Вместо `if pixel.red > 200 && pixel.green < 50` — `(R > 200 && G < 50)`.

5. **Snapshot-семантика.** Пользователь ожидает, что чтение и запись не пересекаются — язык гарантирует это за счёт разделения буферов, без явного копирования со стороны разработчика.

6. **Поэтапное усложнение.** Императивные циклы → простой `->` с предикатом → мульти-ветвление → лямбды. Можно начать с минимальной подгруппы языка и осваивать остальное по мере необходимости.

## 1. Спецификация языка

### 1.1. Синтаксис объявления переменных и подпрограмм

**Объявление переменных:** явное указание типа (свойство 1). Точка с запятой в конце **не ставится**. Синтаксис: `<тип> <имя> = <выражение>`. Инициализирующее выражение может быть константным. Допускается неявное преобразование типов (свойство 2): `int` автоматически становится серым `color`.

```go
// Примеры инициализации
int width = 800
float scale = 0.5
bool flag = true
string initial = "c"
string name = "photo.jpg"

// Структура pixel
pixel center = {x: 100, y: 100}

// Неявное преобразование (int -> color): белый серый
color white = 255

// Кортеж и структура — тоже самостоятельные выражения-литералы
color bg = (10, 20, 30)
color fg = {R: 255, G: 0, B: 0}
```

**Литералы `color` (нетерминал `colorLiteral`):**
```
colorLiteral ::= IntegerLiteral                          // серый: все каналы равны
               | '(' expr ',' expr ',' expr ')'           // каналы R, G, B
               | '{' 'R' ':' expr ',' 'G' ':' expr ',' 'B' ':' expr '}'
               | 'color' '(' expr ',' expr ',' expr ')'   // ≡ форме 2, явный конструктор
```
Отдельного типа «кортеж» в языке нет: форма `(e1, e2, e3)` существует только как литерал цвета. Форма `color(R, G, B)` — тот же кортеж с явным маркером (удобна в предикатах потока для сборки контекстных переменных). Внутри `.color(...)` тройка пишется как три отдельных аргумента перегруженного билтина, а не как кортеж-литерал (см. п. 1.5).

**Объявление подпрограмм:** с ключевым словом `func`. Перегрузка пользовательских подпрограмм **отсутствует** — имена функций уникальны (контроль лаб. 4). Запрет касается только `func`: встроенные функции могут иметь несколько сигнатур — это часть их спецификации (например, `color`, см. п. 1.4–1.5). Все подпрограммы объявляются **в начале программы** до `func void main()`. Параметры передаются **по значению**, возврат — через `return`.

Синтаксис: `func <тип_возврата> <имя>(<параметры>) { <тело> }`

`func` — ключевое слово; в позиции начала объявления (`func void main() {...}`) оно вводит подпрограмму, а в позиции типа параметра встроенных методов (`image.map(func fn)`) обозначает ожидаемую лямбду. Анализатор различает эти случаи по контексту (ключевое слово vs. имя типа в списке параметров).

```go
// Функция с параметрами
func color makeBrighter(color c, float k) {
    return c * k
}

// Функция без параметров
func int getWidth() {
    return 1920
}
```

**Область видимости:** глобальная — вне подпрограмм, локальная — внутри подпрограммы. Блоки `{ }` область не создают: переменные, объявленные в `{ }` (включая переменную заголовка `for`), видимы во всей функции; вложенные области создают подпрограммы (свойство 4=1). Следствия, важные для лаб. 4:
* повторное объявление того же имени в одной функции — семантическая ошибка (два `for int j` в одной функции запрещены; форма `for j = 0` без типа не предусмотрена — используйте другое имя);
* объявление в теле цикла выполняется при каждой итерации (инициализация каждый раз заново), но видимость переменной — вся функция (переменная цикла видна и после цикла).

### 1.2. Синтаксис операций над данными (14 операций)

Арифметические, логические операции и операции доступа. Приоритет — стандартный.

| Категория | Операции | Семантика |
| :--- | :--- | :--- |
| Арифметические | `+`, `-`, `*`, `/`, `%` | Для чисел; `+`, `-`, `*` переопределены для `color` (поканальные); `*` для `color * float` — масштабирование яркости; `+` для `string` — конкатенация с неявным приведением `int/float/bool → string` |
| Сравнения | `==`, `!=`, `>`, `<` | Для чисел; `==`/`!=` для любых встроенных типов |
| Логические | `&&`, `\|\|`, `!` | Для `bool` |
| Индексация | `[]` | Доступ к пикселю: `img[x, y]`, возвращает `color`; чтение/присваивание |
| Доступ | `.` | Доступ к полю структуры или вызов метода: `p.x`, `p.R`, `img.resize()` |

```go
// Примеры выражений
int sum = a + b * 10
color res = (c1 + c2) / 2
bool check = (x > 0) && (y < 100)

// Сложные составные выражения со скобками
color mid = ((px * 1.2) + 20) % 256
int magnitude = sqrt( (gx*gx) + (gy*gy) )
```

### 1.3. Синтаксис всех управляющих конструкций

Стиль Go: **нет круглых скобок** вокруг условия, тело всегда в явных фигурных скобках `{ }` (свойство 5).

**Условный оператор (`if-else`):**
```go
if x > 10 {
    print("X is big")
} else {
    print("X is small")
}
```

**Многовариантный оператор (`switch-case`)** — по свойству 6=2. Без проваливания (fallthrough), как в Go; ветка `default` — аналог `else`:
```go
switch magnitude {
case 0: { print("черный") }
case 255: { print("белый") }
default: { print("полутон") }
}
```

**Цикл `while` (с предусловием):**
```go
int i = 0
while i < 5 {
    print(i)
    i = i + 1
}
```

**Цикл `until` (с постусловием):**
```go
int i = 0
until i >= 5 {
    print(i)
    i = i + 1
}
```

**Цикл `for` (с итерациями):** `for <инициализация>; <условие>; <шаг> { ... }`
```go
for int j = 0; j < width; j = j + 1 {
    img[j, 0] = 255
}
```

**Досрочный выход (`break` / `continue`)** — для `while`, `until` и `for`:
```go
for int j = 0; j < width; j = j + 1 {
    if img[j, 0].R == 0 {
        continue
    }
    if j > 100 {
        break
    }
    img[j, 0] = 255
}
```
`break` выходит из ближайшего объемлющего цикла, `continue` — переходит к следующей итерации. С терминалом потока `.break()` не путать: тот прерывает весь обход изображения вместе с эпилогом.

**Лямбда-функции** (аргументы `map`, `blend`). Стиль Java: `(аргументы) -> { тело }`:
```go
(color p) -> {
    return p * 1.5
}
```

Параметры лямбды локальны для её тела и могут затенять внешние имена (включая неявный `p` потока — внутри `(color p) -> {...}` это параметр). Тело видит внешние имена только на чтение (захват по значению, свойство 8); присваивание внешней переменной из лямбды — семантическая ошибка (лаб. 4).

### 1.4. Встроенные функции

**Ввод/вывод (TASKS.md п. 3.4.1):**
* `read()` — считывает строку или число из стандартного ввода.
* `print(value)` — выводит значение (строку, число, информацию об изображении) в консоль.

**Информационные:**
* `width(image img)` — ширина изображения (`int`).
* `height(image img)` — высота изображения (`int`).

**Работа с файлами:**
* `load(string path)` — загружает изображение из файла, возвращает `image`.
* `save(image img, string path)` — сохраняет изображение в файл.

**Формы вызова: один билтин — разный синтаксис.** `img.f(args)` ≡ `f(img, args)` — методная форма с неявным первым аргументом. В потоке `.f(args)` изображение тоже подставляется неявно (выходной буфер), а пер-пиксельные модификаторы дополнительно протаскивают текущий пиксель (см. эпилог в п. 1.5 про whole-image семантику `::`).

| Билтин | Свободная | Метод `img.f()` | Модификатор `.f()` в потоке |
| :--- | :---: | :---: | :---: |
| `load` | ✅ | — | — |
| `save` | ✅ | ✅ | ✅ (терминал; в ветке — отложенно, см. эпилог) |
| `print` | ✅ | — | ✅ (tap, в любом месте цепочки) |
| `width/height/sqrt/read` | ✅ | — | — |
| `resize/rotate/crop/map` | ✅ | ✅ | — |
| `grayscale/invert/blur` | — | ✅ | ✅ |
| `color/brightness/pass/vignette/sobel` | — | — | ✅ |
| `blend/subtract` | — | — | ✅ (с лямбдой) |
| `count/break` | — | — | ✅ (терминалы веток) |

**Математические:**
* `sqrt(float x)` — квадратный корень.

**Методы трансформации (chainable, возвращают `image`):**
* `image.resize(int w, int h)` — изменяет размер.
* `image.rotate(float angle)` — поворачивает на угол.
* `image.crop(int x, int y, int w, int h)` — вырезает фрагмент.
* `image.grayscale()` — оттенки серого.
* `image.invert()` — негатив.
* `image.blur(int radius)` — Box Blur по ядру `(2·radius+1) × (2·radius+1)`.
* `image.map(func fn)` — применяет лямбду к каждому пикселю.

```go
image src = load("photo.jpg")

// Лямбда принимает текущий пиксель и возвращает новый color
image warm = src.map((color p) -> {
    return p * 1.3
})
save(warm, "warm.jpg")
```

> **Арность лямбд.** `map` — один параметр (текущий пиксель `p`); `blend`/`subtract` в потоке — два (`(color src, color overlay)`, пиксели основного и второго изображений). См. сниппеты мульти-изображений в п. 1.5.

### 1.5. Потоковый оператор `->` (ключевая особенность языка)

Главное свойство ImgLang: декларативная потоковая обработка (Stream Syntax), аналог LINQ для графики.

#### Базовый синтаксис

```
<источник> -> (<предикат>) .метод1().метод2().терминал()
```

Источник потока — переменная `image` или вызов `load(...)` (загрузка прямо в потоке).

Оператор `->` — это switch по пикселям: для каждого пикселя ветки идут сверху вниз; каждая ветка, чей предикат истинен, выполняется по очереди, остальные пропускаются. Значение текущего пикселя протаскивается по цепочкам совпавших веток. Логика чтения: *«Взять картинку → для каждого пикселя сверху вниз: (где условие) → модифицировать → сохранить»*.

**Предикаты (условия):**
1. Встроенные функции-предикаты — работают с «текущим» пикселем неявно, без аргументов:
   * `isColor(color c)` — расстояние по RGB не превышает порога (по умолчанию 48); пиксель считается «похожим» на заданный цвет.
   * `isBright()` / `isDark()` — яркость выше/ниже среднего.
   * `isContour()` — пиксель принадлежит контуру (ребру).
   * `isRed()` / `isGreen()` / `isBlue()` — быстрые проверки доминирования соответствующего канала.
2. Логическое выражение над **переменными контекста** текущего пикселя: `R`, `G`, `B` — каналы цвета, `x`, `y` — координаты. Компилятор сам подставляет текущий пиксель.
   ```go
   src -> ((R + G + B) / 3 < 50) .color(255) .save("remove_black.jpg")
   ```
3. Вызов пользовательской функции, принимающей `color`. Контекстные переменные собираются в структуру цвета через синтаксис `color(R, G, B)`:
   ```go
   src -> (isTooBright(color(R, G, B))) .brightness(0.5) ::save("out.jpg")
   ```

**Отрицание и комбинации:** перед вызовом-предикатом допускается префикс `!` — `(!(isRed()))` означает «все пиксели, кроме красных». Предикаты комбинируются через `&&`, `||`, `!` со сравнениями над контекстными переменными: `(!(isDark()) && !(isBright()))` — «ни тёмные, ни яркие». Такие комбинации нужны для середины цепочек; «все остальные» штатно пишется через ветку `: else` (см. ниже).

**Модификаторы (возвращают `image`):**  
Каждый модификатор получает от потока текущий пиксель `p` (color) и возвращает новый `color`, который записывается в выходной буфер.

* `.invert()` — негатив: каждый канал меняется на противоположный.  
  `result = {R: 255-p.R, G: 255-p.G, B: 255-p.B}`

* `.grayscale()` — обесцвечивание по средней яркости каналов.  
  `g = (p.R + p.G + p.B) / 3; result = {R: g, G: g, B: g}`

* `.color(...)` — покрасить пиксель в заданный цвет, полностью заменяя исходный.  
  Формы: `.color(серый)` — каждый канал = серый (один аргумент `int`/`color`); `.color(R, G, B)` — три отдельных целочисленных аргумента (каналы по отдельности, **не** кортеж-литерал); `.color({R: r, G: g, B: b})` — структура цвета.  
  `result = заданный_цвет`

* `.brightness(float k)` — масштабировать яркость каждого канала.  
  `result = {R: clamp(p.R * k, 0, 255), G: clamp(p.G * k, 0, 255), B: clamp(p.B * k, 0, 255)}`  
  При `k < 1` — затемнение, при `k > 1` — осветление.

* `.pass()` — пропустить пиксель без изменений.  
  `result = p`  
  Используется в мульти-ветвлении, чтобы явно указать «не трогать эту группу пикселей».

* `.vignette()` — эффект виньетки: затемнение краёв кадра. Коэффициент затухания зависит от расстояния пикселя до центра изображения.  
  `dist = sqrt((x - cx)² + (y - cy)²) / maxDist; k = 1 - dist²; result = p * k`

* `.blur(int radius)` — Box Blur по ядру `(2·radius+1) × (2·radius+1)`. Каждый канал текущего пикселя заменяется средним арифметическим по окрестности (снимок — snapshot-семантика, чтение из оригинала).  
  `result = avg(p[x-i, y-j])` для `-radius ≤ i,j ≤ radius`

* `.sobel()` — оператор Собеля: карта краёв по каналу G (зелёный). Магнитуда градиента от свёрток с ядрами Gx, Gy.  
  `gx = (-1·pTL.G)+(0·pTC.G)+(1·pTR.G)+(-2·pML.G)+(0·pMR.G)+(2·pBL.G)+(-1·pBL.G)+(0·pBC.G)+(1·pBR.G)`  
  `gy = (-1·pTL.G)+(-2·pTC.G)+(-1·pTR.G)+(0·pML.G)+(0·pMR.G)+(1·pBL.G)+(2·pBC.G)+(1·pBR.G)`  
  `magnitude = sqrt(gx²+gy²); result = clamp(magnitude, 0, 255)` — серый цвет.

**Отладочный tap (может стоять в любом месте цепочки):**
* `.print(string msg)` — выводит сообщение (допускает `x`, `y`, `R`, `G`, `B`) и **возвращает текущий пиксель без изменений**, пробрасывая его на следующий этап цепочки; тот же `print`, что и вне потока. Срабатывает для каждого пикселя, дошедшего до него по ветке.

**Терминальные операции (завершают поток; терминал — последний в цепочке):**
* `.save(string path)` — сохранить результат в файл.
* `.count()` — вернуть `int` — количество пикселей, прошедших фильтр. Цепочка с `.count()` является **выражением** типа `int` и может присваиваться переменной без внешних скобок: `int n = src -> (isRed()) .count()`.
* `.break()` — прервать обработку **всего** изображения (аналог `break` в цикле; полезно для поиска «первого попавшегося» пикселя).

**Методы мульти-изображений (вызываются в цепочке):**  
Для каждого текущего пикселя `p` основного изображения берётся пиксель `q` второго изображения `other` с теми же координатами `(x, y)`. Результат вычисляется через заданную лямбду — так пользователь сам определяет формулу смешивания (сложение, вычитание, умножение, усреднение с весами и т.д.).

* `.blend(image other, func lambda)` — накладывает `other` поверх текущего; лямбда принимает `(color src, color overlay) -> color`.  
  `result = lambda(p, q[x, y])`

* `.subtract(image other, func lambda)` — поканальная обработка двух изображений; лямбда принимает `(color src, color other) -> color`.  
  `result = lambda(p, q[x, y])`  
  Типичное применение: разностная карта — `(src, ov) -> { return src - ov }`, выявление изменений между кадрами.

#### Мульти-ветвление в потоке (`:` и `::`)

```
<image> -> (<pred1>) <chain1>
   : (<pred2>) <chain2>
   : ...
   : else <chain_else>
   :: <финальная_цепочка>
```

* **`:`** — следующая условная стадия (аналог `case`, но без `break`). Для каждого пикселя предикаты проверяются сверху вниз по **исходному snapshot**; цепочка выполняется для **каждой** ветки, чей предикат вернул `true`. Совпавшие преобразования накапливаются в порядке веток.
* **`()`** — то же, что `(true)`: безусловная стадия, выполняется для всех пикселей (включая те, для которых уже сработали ветки выше).
* **`: else`** — else-ветка: выполняется для пикселя тогда и только тогда, когда ни один предикат выше не был истинен (аналог `default`). Единственная на поток, стоит строго последней среди условных веток — ветки после неё запрещены грамматикой.
* **`::`** — эпилог: выполняется **один раз** после полного прохода по всем пикселям (аналог `finally`, но один раз, а не на пиксель). Если обход прерван через `.break()`, эпилог пропускается. Хочешь операцию по всем пикселям построчно — это обычная ветка `()` с цепочкой, а не `::`.

#### Эпилог (`::`)

Цепочка эпилога — операции над целым результирующим изображением: работает как обычная цепочка методов из п. 1.4. Модификаторы применяются ко всему буферу сразу и читают текущий результирующий буфер (а не исходный snapshot).

* Разрешено: модификаторы (whole-image семантика), `.print(msg)` — один раз (контекстные `x`, `y`, `R`, `G`, `B` недоступны — нет текущего пикселя; их использование там — семантическая ошибка), `.save(path)` — сохранение результата.
* Запрещено (семантические ошибки, лаб. 4): `.count()` — не к чему привязать (только в ветках, к предикату); `.break()` — прерывать нечего (только в ветках).
* `.save(path)` в ветке — отложенная регистрация: выполняется после модификаторов эпилога; несколько `save` выполняются все. `.break()` в ветке немедленно прекращает обход и пропускает эпилог.

#### Snapshot-семантика

Чтобы ручные свёртки (blur, Sobel) работали корректно, поток работает с **снимком (snapshot)** оригинала:
* все чтения `img[x, y]` внутри предикатов и лямбд идут из **исходного** изображения;
* предикаты всех веток проверяются по исходному снимку — записи соседних веток они не видят;
* все модификации (`.color()`, `.invert()` и т.д.) пишутся в **новый** буфер; значение текущего пикселя протаскивается по цепочкам совпавших веток по очереди.

Поэтому при последовательном обходе пикселей артефактов «наплыва» нет, а доступ к соседям `img[x+i, y+j]` из пользовательских функций позволяет реализовать любые свёртки. Встроенные методы (`.blur()` и т.п.) остаются для производительности.

#### Сниппеты базового потока

```go
image src = load("forest.jpg")

// Стрелочка -> открывает поток; .save() в ветке сохраняет итог после эпилога
src -> (isRed()) .invert() .save("inverted_reds.jpg")

// Загрузка прямо в потоке: источник-вызов вместо переменной
load("logo.jpg") -> (isRed()) .invert() ::save("logo_out.jpg")

// Логическое выражение в предикате: очень темные -> сделать белыми
image bw = load("bw.jpg")
bw -> ((R + G + B) / 3 < 50) .color(255) .save("remove_black.jpg")

// Контуры -> покрасить в зеленый
image shapes = load("shapes.jpg")
shapes -> (isContour()) .color({R:0, G:255, B:0}) .save("green_contours.jpg")

// Несколько потоков на одной картинке
image cat = load("cat.jpg")
cat -> (isRed()) .invert() .save("cat_red_inv.jpg")
cat -> (isBright()) .brightness(0.5) .save("cat_dim.jpg")

// Терминал .count() — выражение типа int
int reds = cat -> (isRed()) .count()
print("Красных пикселей: " + reds)

// print в середине цепочки: отладка с пробросом пикселя дальше
src -> (isRed()) .print("red at " + x + "," + y) .invert() ::save("debug_reds.jpg")
```

#### Сниппеты мульти-ветвления

**Бинаризация (один проход вместо двух):**
```go
func void main() {
    image doc = load("scan.jpg")

    // Если темный -> черный : иначе (ветка else) -> белый :: сохранить
    doc -> (isDark()) .color(0)
       : else .color(255)
       ::save("bw_scan.jpg")
}
```

**Цветовое кодирование по яркости:**
```go
func void main() {
    image src = load("heatmap.jpg")

    src -> (isDark()) .color(0, 0, 255)      // Темные -> Синие
       : (isBright()) .color(255, 0, 0)      // Светлые -> Красные
       : else .color(0, 255, 0)              // Остальные -> Зеленые
       ::save("color_coded.jpg")
}
```

**Поиск дефекта с `.print()` и `.break()`:**
```go
func void main() {
    image details = load("microchip.jpg")

    // Если дефект (красный) -> записать координаты и прервать весь обход
    // :: печатает, только если break ни разу не сработал (дефектов нет)
    details -> (isRed())
              .print("Defect found at: " + x + "," + y)
              .break()
              ::print("No defects found")
}
```

**Ветвление + эпилог (`::` один раз в конце):**
```go
func void main() {
    image src = load("art.jpg")

    // 1. Красные инвертируем : 2. Синие слегка осветляем
    // Ветки выполняются последовательно: красно-синий пиксель получит оба эффекта
    // :: эпилог — виньетка ко всему результату, затем сохранение
    src -> (isRed()) .invert()
       : (isBlue()) .brightness(1.2)
       ::vignette()
          .save("processed.jpg")
}
```

#### Сниппеты мульти-изображений

```go
func void main() {
    image base = load("background.jpg")
    image overlay = load("object.png")

    // Наложение: смешивание каналов основной и накладываемой картинки
    base -> ()
          .blend(overlay, (color src, color over) -> {
              return (src * 0.7) + (over * 0.3)
          })
          ::save("blended.jpg")

    // Разностная карта (например, сравнение кадров)
    image frame1 = load("frame1.jpg")
    image frame2 = load("frame2.jpg")
    frame1 -> () .subtract(frame2, (color a, color b) -> { return a - b }) ::save("difference.jpg")
}
```

#### Сниппеты селективных операций (snapshot + встроенные методы)

Поскольку поток читает исходный снимок, а пишет в новый буфер, встроенные методы `.blur()` и `.sobel()` корректно работают даже в селективном режиме — артефактов «наплыва» нет.

**Селективное размытие (размыть всё, кроме красных объектов):**
```go
func void main() {
    image src = load("photo.jpg")

    // Блюрим всё, кроме красных (предикат-отрицание вместо ветки .pass())
    src -> (!(isRed())) .blur(3)
       ::save("selective_blur.jpg")
}
```

**Оператор Собеля (карта краёв для тёмных участков):**
```go
func void main() {
    image src = load("objects.jpg")

    // Карта краёв только для НЕ ярких участков
    src -> (!(isBright())) .sobel()
       ::save("edges_dark.jpg")
}
```

## 4. Примеры работы компилятора

Полная программа, использующая все конструкции языка: подпрограммы в начале, императивная обработка, потоковая обработка, switch-case, все циклы, неявные преобразования.

```go
// --- Подпрограммы объявляются в начале программы ---

// Императивный стиль: циклы for/while, индексация, неявные преобразования
func image processManual(image img) {
    int w = width(img)
    int h = height(img)

    for int x = 0; x < w; x = x + 1 {
        int y = 0
        while y < h {
            color p = img[x, y]

            if p.R > 200 {
                img[x, y] = 255          // Неявное преобразование int -> color
            } else {
                img[x, y] = p * 0.5      // Затемнение
            }
            y = y + 1
        }
    }
    return img
}

// --- Основная программа ---

func void main() {
    // Инициализация переменных всех типов
    image src = load("photo.jpg")
    int limit = 100
    bool useChain = true
    pixel p = {x: 10, y: 10}
    float k = 1.2

    print("Start processing...")

    if useChain {
        // Императивная обработка
        image res = processManual(src)
        save(res, "output_manual.jpg")
    } else {
        // Потоковая обработка с мульти-ветвлением (ветки выполняются
        // последовательно; третья — ветка else для несовпавших)
        src -> (isRed()) .invert()
           : (R > 200) .brightness(k)
           : else .grayscale()
           ::save("output_chain.jpg")
    }

    // switch-case
    switch limit {
    case 0: { print("Лимит нулевой") }
    case 100: { print("Стандартный лимит") }
    default: { print("Нестандартный лимит: " + limit) }
    }

    // Цикл until (постусловие)
    int i = 0
    until i == 3 {
        print("Processing step " + i)
        i = i + 1
    }

    print("Done")
}
```

*Примечание:* предикат ветки записывается выражением над переменными контекста (`R`, `G`, `B`, `x`, `y`), встроенной функцией-предикатом или пользовательской функцией (см. п. 1.5).
