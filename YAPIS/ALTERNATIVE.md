## 0.5. Обоснование предметно-ориентированного подхода

ImgLang — предметно-ориентированный язык (DSL) для обработки изображений. Его цель — сократить разрыв между задачей («инвертировать красные пиксели») и кодом, который её описывает.

### 0.5.1. Синтаксический сахар для предметной области

Повторяющиеся паттерны обработки изображений свёрнуты в лаконичные конструкции, отсутствующие в универсальных языках:

| Доменная концепция | В универсальном языке (Python/C++) | В ImgLang |
| :--- | :--- | :--- |
| Загрузить изображение | `cv2.imread("f.jpg")` — импорт, BGR-порядок, numpy-массив | `Load("f.jpg")` |
| Пройти по всем пикселям с фильтром | `for i in range(h): for j in range(w): if is_red(img[i,j]): ...` | `If pixel Is Red: { apply Invert }` |
| Классификация по яркости | `if is_dark: c=0 else c=255` с циклом | `If pixel Is Dark: { apply Color(0) } If Not pixel Is Dark: { apply Color(255) }` |
| Применить оператор Собеля | Свёртка с двумя ядрами, магнитуда — ~20 строк | `Apply Sobel` |

**Ключевые сокращения:**

1. **Декларативный поток** — `If pixel Is ...` вместо вложенных циклов по пикселям + условного оператора.
2. **Неявное преобразование `Integer → Color`** — `Color white = 255` избавляет от конструктора.
3. **Литералы цвета без конструктора** — `255`, `(0, 0, 255)`, `{R:0, G:0, B:255}`, `Color(0, 0, 255)` — самостоятельные выражения (см. нетерминал `colorLiteral` в п. 1.1).
4. **Индексация `img[x, y]`** — естественное для графики lvalue/rvalue.
5. **Предикаты в потоке** — `Red`, `Bright` и выражения над `R`, `G`, `B`, `x`, `y`.
6. **Мульти-ветвление** — классификация пикселей без лесенок `if-else` и временных буферов.

### 0.5.2. Лёгкость восприятия для специалистов

1. **Терминология предметной области.** Имена встроенных функций (`Load`, `Save`, `Grayscale`, `Blur`, `Sobel`, `Invert`, `Resize`, `Crop`, `Rotate`) и предикатов (`Red`, `Bright`, `Contour`) взяты из лексикона фотографов и дизайнеров.

2. **Декларативный стиль потока.** `If pixel Is Red: { apply Invert, Save("out.jpg") }` читается как инструкция естественного языка.

3. **Минимум теории.** Язык не требует знания классов, наследования, обобщённых типов, указателей, исключений или перегрузки операторов.

4. **Предикаты как естественные вопросы.** Вместо `if brightness(pixel) > threshold` — `If pixel Is Bright:`. Вместо `if pixel.red > 200 && pixel.green < 50` — `If R > 200 And G < 50`.

5. **Snapshot-семантика.** Чтение и запись не пересекаются за счёт разделения буферов — без явного копирования.

6. **Поэтапное усложнение.** Императивные циклы → `If pixel Is ...` → мульти-ветвление → лямбды.

## 1. Спецификация языка

### 1.1. Синтаксис объявления переменных и подпрограмм

**Объявление переменных:** явное указание типа. Точка с запятой в конце **не ставится**. Синтаксис: `<тип> <имя> = <выражение>`. Допускается неявное преобразование типов: `Integer` автоматически становится серым `Color`.

```
Integer width = 800
Float scale = 0.5
Boolean flag = True
String initial = "c"

Pixel center = {x: 100, y: 100}

Color white = 255   // Неявное преобразование Integer -> Color

Color bg = (10, 20, 30)
Color fg = {R: 255, G: 0, B: 0}
```

**Литералы `Color` (нетерминал `colorLiteral`):**
```
colorLiteral ::= IntegerLiteral                          // серый: все каналы равны
               | '(' expr ',' expr ',' expr ')'           // каналы R, G, B
               | '{' 'R' ':' expr ',' 'G' ':' expr ',' 'B' ':' expr '}'
               | 'Color' '(' expr ',' expr ',' expr ')'   // ≡ форме 2, явный конструктор
```
Отдельного типа «кортеж» в языке нет: форма `(e1, e2, e3)` существует только как литерал цвета. Внутри `apply Color(R, G, B)` тройка пишется как три отдельных аргумента перегруженной операции, а не как кортеж-литерал (см. п. 1.5).

**Объявление подпрограмм:** с ключевым словом `Function`. Имена функций уникальны — перегрузка пользовательских подпрограмм отсутствует (контроль лаб. 4). Запрет касается только `Function`: встроенные операции могут иметь несколько сигнатур — это часть их спецификации (например, `Color`). Все подпрограммы объявляются **в начале программы** до `Function Void main()`. Параметры передаются **по значению**. Тело функции — в явных `{ }`.

Синтаксис: `Function <тип_возврата> <имя>(<параметры>): { <тело> }`. При вызове функций без параметров скобки опускаются: `Read`, `Stop`, `getWidth`.

```
Function Color makeBrighter(Color c, Float k): {
    Return c * k
}

Function Integer getWidth(): {
    Return 1920
}
```

**Область видимости:** глобальная — вне подпрограмм, локальная — внутри подпрограммы. Блоки `{ }` область не создают: переменные, объявленные в `{ }` (включая переменную заголовка `For`), видимы во всей функции. Следствия, важные для лаб. 4:
* повторное объявление того же имени в одной функции — семантическая ошибка (два `For Integer j` в одной функции запрещены; формы `For j = 0` без типа нет — используйте другое имя);
* объявление в теле цикла выполняется при каждой итерации (инициализация каждый раз заново), но видимость переменной — вся функция (переменная цикла видна и после цикла).

### 1.2. Синтаксис операций над данными (14 операций)

| Категория | Операции | Семантика |
| :--- | :--- | :--- |
| Арифметические | `+`, `-`, `*`, `/`, `%` | Для чисел и строк (`+` — конкатенация; `String + любой тип` — неявное приведение операнда к `String`); `+`, `-`, `*` переопределены для `Color` (поканальные); `*` для `Color * Float` — масштабирование яркости |
| Сравнения | `==`, `Not ==`, `>`, `<` | Для чисел; `==`/`Not ==` для любых встроенных типов |
| Логические | `And`, `Or`, `Not` | Для `Boolean`. `Not` — унарный префиксный оператор (аналог `!`). `Not ==` — единый токен, разбирается раньше `Not` |
| Индексация | `[]` | Доступ к пикселю: `img[x, y]`, возвращает `Color`; чтение/присваивание |
| Доступ | `.` | Доступ к полю структуры: `p.x`, `p.R`, `c.R` |

```
Integer sum = a + b * 10
Color res = (c1 + c2) / 2
Boolean check = (x > 0) And (y < 100)

Color mid = ((px * 1.2) + 20) % 256
Integer magnitude = Sqrt( (gx*gx) + (gy*gy) )
```

### 1.3. Синтаксис всех управляющих конструкций

Двоеточие перед телом, тело в явных фигурных скобках `{ }`.

**Условный оператор (`If-Otherwise`):**
```
If x > 10: {
    Print("X is big")
} Otherwise: {
    Print("X is small")
}
```

**Многовариантный оператор (`Switch-Case`):**
```
Switch magnitude: {
    Case 0: { Print("черный") }
    Case 255: { Print("белый") }
    Otherwise: { Print("полутон") }
}
```

**Цикл `While`:**
```
Integer i = 0
While i < 5: {
    Print(i)
    i = i + 1
}
```

**Цикл `Until`:**
```
Integer i = 0
Until i == 3: {
    Print("Processing step " + i)
    i = i + 1
}
```

**Цикл `For`:** `For <инициализация>; <условие>; <шаг>: { ... }`
```
For Integer j = 0; j < width; j = j + 1: {
    img[j, 0] = 255
}
```

**Досрочный выход (`Break` / `Continue`)** — для `While`, `Until` и `For`:
```
For Integer j = 0; j < width; j = j + 1: {
    If img[j, 0].R == 0: {
        Continue
    }
    If j > 100: {
        Break
    }
    img[j, 0] = 255
}
```
`Break` выходит из ближайшего объемлющего цикла, `Continue` — переходит к следующей итерации. С терминалом потока `Stop` не путать: тот прерывает весь обход изображения вместе с эпилогом.
> **Примечание.** Переменная `j`, объявленная в заголовке `For`, видна во всей функции (блоки не создают область видимости — свойство 4). Точки с запятой `;` в `For` — разделители секций цикла (инициализация; условие; шаг), а не терминаторы.

**Лямбда-функции** (аргументы `Map`, `Blend`): `Do On Each: { тело }`
```
Do On Each: {
    Return p * 1.5
}
```

Параметры лямбды локальны для её тела и могут затенять внешние имена (включая неявные `p` / `src` / `over` потока). Тело видит внешние имена только на чтение (захват по значению); присваивание внешней переменной из лямбды — семантическая ошибка (лаб. 4).

### 1.4. Встроенные функции

**Ввод/вывод:**
* `Read` — считывает строку или число из стандартного ввода.
* `Print(value)` — выводит значение в консоль.

**Информационные:**
* `Width(Image img)` — ширина изображения (`Integer`).
* `Height(Image img)` — высота изображения (`Integer`).

**Работа с файлами:**
* `Load(string path)` — загружает изображение из файла, возвращает `Image`.
* `Save(Image img, string path)` — сохраняет изображение в файл.

**Математические:**
* `Sqrt(Float x)` — квадратный корень.

**Аналитические:**
* `Count(Image img, expr)` — возвращает `Integer` — количество пикселей, для которых `expr` истинно. `expr` — встроенное имя предиката (`Red`, `Bright`, …) либо булево выражение над `R`, `G`, `B`, `x`, `y`. Выражение вычисляется **лениво (per-pixel)** — как если бы каждый пиксель подставлялся в `WHERE` SQL-запроса. Пример: `Count(cat, R > 200)` вернёт число красноватых пикселей.

**Функции трансформации (принимают `Image` первым аргументом, возвращают `Image`):**
* `Resize(Image img, Integer w, Integer h)` — изменяет размер.
* `Rotate(Image img, Float angle)` — поворачивает на угол.
* `Crop(Image img, Integer x, Integer y, Integer w, Integer h)` — вырезает фрагмент.
* `Grayscale(Image img)` — оттенки серого.
* `Invert(Image img)` — негатив.
* `Blur(Image img, Integer radius)` — размытие (Box Blur).
* `Map(Image img, fn)` — применяет лямбду к каждому пикселю. `fn` — лямбда `Do On Each: { }`, не является значением первого класса (см. замечание ниже).

Эти функции можно использовать цепочкой: `Blur(Invert(src), 3)` — вложенный вызов. Внутри потока `Process` модификаторы применяются к текущему пикселю неявно, поэтому `Invert`, `Blur(3)` и т.д. пишутся без аргумента-изображения.

**Формы вызова: одна операция — разный синтаксис.** В потоке `apply F(args)` — та же операция, изображение подставляется неявно (выходной буфер), а пер-пиксельные модификаторы дополнительно протаскивают текущий пиксель (см. эпилог в п. 1.5 про whole-image семантику `Finally`).

| Операция | Свободная `F(...)` | `apply` в потоке |
| :--- | :---: | :---: |
| `Load` | ✅ | — |
| `Save` | ✅ | ✅ (в ветке — отложенно, см. эпилог) |
| `Print` | ✅ | ✅ (statement тела ветки) |
| `Width/Height/Sqrt/Read/Count` | ✅ | — |
| `Resize/Rotate/Crop/Map` | ✅ (вложенные вызовы) | — |
| `Grayscale/Invert/Blur` | ✅ | ✅ |
| `Color/Brightness/Nothing/Vignette/Sobel` | — | ✅ |
| `Blend/Subtract` | ✅ | ✅ (с лямбдой) |
| `Stop` | ✅ (без скобок) | ✅ (только в ветках) |

```
Image src = Load("photo.jpg")

// Лямбда принимает текущий пиксель (неявная переменная p) и возвращает новый Color
Image warm = Map(src, Do On Each: { Return p * 1.3 })
Save(warm, "warm.jpg")
```

> **Арность лямбд.** `Map` — один неявный параметр (текущий пиксель `p`); `Blend`/`Subtract` — два (`src` и `over`, пиксели основного и второго изображений). См. сниппеты мульти-изображений в п. 1.5.

### 1.5. Потоковый оператор (ключевая особенность)

Главное свойство ImgLang: декларативная потоковая обработка в синтаксисе естественного языка. Поток — это switch по пикселям: для каждого пикселя ветки идут сверху вниз; каждая ветка с истинным условием выполняется по очереди, остальные пропускаются. Значение текущего пикселя протаскивается по цепочкам совпавших веток.

#### Базовый синтаксис

Поток начинается с ключевого слова `Process`, за которым следует источник (путь к файлу в виде строки или переменная `Image`; вызов `Load(...)` источником не является — сначала присвойте его переменной), двоеточие и тело в `{ }`. Внутри тела — ветки `If pixel Is ...:`, `Otherwise:` и `Finally:`.

```
Process "photo.jpg": {
    If pixel Is Red: { apply Invert }
    Finally: { Save("out.jpg") }
}
```

Либо с заранее загруженной переменной:

```
Image img = Load("photo.jpg")
Process img: {
    If pixel Is Red: { apply Invert }
    If Not pixel Is Red: { apply Grayscale }
    Finally: { Save("result.jpg") }
}
```

Логика: *«Взять изображение → (где условие) → применить модификаторы → в конце применить финальные операции ко всем»*.

**Предикаты (условия):**
1. Встроенные функции-предикаты — работают с «текущим» пикселем неявно, префикс `is` опускается (он уже в синтаксисе `If pixel Is ...`): `Color(Color c)`, `Bright`, `Dark`, `Contour`, `Red`, `Green`, `Blue`.
2. Логическое выражение над переменными контекста: `R`, `G`, `B`, `x`, `y`.
   ```
   Process "bw.jpg": {
       If (R + G + B) / 3 < 50: { apply Color(255) }
       Finally: { Save("remove_black.jpg") }
   }
   ```
3. Отрицание: перед условием допускается префикс `Not` — `If Not pixel Is Red:` означает «все пиксели, кроме красных». `Not` комбинируется с `And`/`Or`: `If Not pixel Is Dark And Not pixel Is Bright:` — «ни тёмные, ни яркие». Такие комбинации нужны для середины цепочек; «все остальные» штатно пишется через ветку `Otherwise` (см. ниже).

**Модификаторы (применяются к текущему пикселю):**

Каждый модификатор получает от потока текущий пиксель `p` (Color) и возвращает новый `Color`, который записывается в выходной буфер. Через запятую можно указать несколько модификаторов: `apply Invert, Blur(3), Brightness(0.5)`.

* `apply Invert` — негатив: `result = {R: 255-p.R, G: 255-p.G, B: 255-p.B}`
* `apply Grayscale` — обесцвечивание: `g = (p.R + p.G + p.B) / 3; result = {R: g, G: g, B: g}`
* `apply Color(значение)` — покрасить: `apply Color(255)`, `apply Color(0, 0, 255)`, `apply Color({R:0, G:255, B:0})`
* `apply Brightness(k)` — масштабировать яркость: при `k < 1` затемнение, при `k > 1` осветление
* `apply Nothing` — пропустить пиксель без изменений
* `apply Vignette` — эффект виньетки: затемнение краёв
* `apply Blur(radius)` — Box Blur по окрестности
* `apply Sobel` — оператор Собеля (карта краёв)
* `apply Blend(Image other, Do On Each: { ... })` — накладывает `other` поверх текущего; лямбда принимает `(src, over)`
* `apply Subtract(Image other, Do On Each: { ... })` — поканальная обработка двух изображений; лямбда принимает `(src, over)`

> **Примечание о неявной контекстной передаче.** Внутри потока `Blend` и `Subtract` работают как модификаторы: для каждого текущего пикселя `p` берётся пиксель `q` из `other` с теми же координатами, лямбда вычисляет результат. Вне потока они вызываются как обычные функции: `Blend(base, overlay, Do On Each: { ... })`.

**Терминальные операции:**
* `Save("path")` — сохранить результат в файл.
* `Print(msg)` — вывод отладочной информации (допускает `x`, `y`, `R`, `G`, `B`); тот же `Print`, что и вне потока. В теле ветки это обычный statement: на преобразование пикселя не влияет и может стоять перед `apply`-модификаторами (отладка с пробросом дальше по телу ветки). Срабатывает для каждого пикселя, дошедшего до него по ветке.
* `Stop` — прервать обработку всего изображения.

**Замечания:**
* **`Save` внутри `Process`:** вызов `Save("path")` в блоке `Finally` неявно сохраняет результатное изображение; второй аргумент (`Image`) не требуется.
* **Лямбды (`Do On Each: { }`)** — синтаксический сахар для позиций `Map`, `Blend`, `Subtract`. Не являются значениями первого класса; тип `Function` не входит в список встроенных типов языка. Внутри лямбды неявно доступны переменные: `p` (для `Map` — текущий пиксель), `src` и `over` (для `Blend`/`Subtract` — пиксели основного и второго изображения).

#### Мульти-ветвление

```
Process "img.jpg": {
    If pixel Is <pred1>: { apply <chain1> }
    If pixel Is <pred2>: { apply <chain2> }
    ...
    Otherwise: { apply <chain_else> }
    Finally: { apply <final_chain> }
}
```

* Каждая ветка `If pixel Is ...:` проверяется сверху вниз по **исходному snapshot**; тело выполняется для **каждой** ветки с истинным условием (аналог `case`, но без `break`). Совпавшие преобразования накапливаются в порядке веток.
* `Otherwise:` — else-ветка: выполняется для пикселя тогда и только тогда, когда ни одно условие выше не было истинным (аналог `default` в `Switch-Case`). Единственная на поток, стоит строго последней среди условных веток — ветки `If` после неё запрещены грамматикой. Безусловная стадия в середине тела при необходимости пишется как `If True:`.
* `Finally:` — эпилог: выполняется **один раз** после полного прохода по всем пикселям. Если обход прерван через `Stop`, эпилог пропускается. Операция по всем пикселям построчно — это обычная ветка (`If True:`), а не `Finally`.

#### Эпилог (`Finally`)

Тело эпилога — операции над целым результирующим изображением: работает как обычная цепочка функций из п. 1.4. `apply`-модификаторы применяются ко всему буферу сразу и читают текущий результирующий буфер (а не исходный snapshot).

* Разрешено: модификаторы (whole-image семантика), `Print(msg)` — один раз (контекстные `x`, `y`, `R`, `G`, `B` недоступны — нет текущего пикселя; их использование там — семантическая ошибка), `Save("path")` — сохранение результата.
* Запрещено (семантические ошибки, лаб. 4): `Stop` — прерывать нечего (только в ветках).
* `Save(...)` в ветке — отложенная регистрация: выполняется после модификаторов эпилога; несколько `Save` выполняются все. `Stop` в ветке немедленно прекращает обход и пропускает эпилог.

#### Snapshot-семантика

Поток работает с **снимком (snapshot)** оригинала:
* все чтения `img[x, y]` внутри предикатов и лямбд идут из **исходного** изображения;
* условия всех веток проверяются по исходному снимку — записи соседних веток они не видят;
* все модификации пишутся в **новый** буфер; значение текущего пикселя протаскивается по цепочкам совпавших веток по очереди.

Поэтому встроенные методы (`Blur`, `Sobel`) корректны в селективном режиме — артефактов «наплыва» нет.

#### Сниппеты базового потока

```
// Только красные — инвертировать, затем сохранить
Process "forest.jpg": {
    If pixel Is Red: { apply Invert }
    Finally: { Save("inverted_reds.jpg") }
}

// Очень тёмные — сделать белыми
Process "bw.jpg": {
    If (R + G + B) / 3 < 50: { apply Color(255) }
    Finally: { Save("remove_black.jpg") }
}

// Контуры — покрасить в зелёный
Process "shapes.jpg": {
    If pixel Is Contour: { apply Color({R:0, G:255, B:0}) }
    Finally: { Save("green_contours.jpg") }
}

// Несколько потоков на одной картинке
Process "cat.jpg": {
    If pixel Is Red: { apply Invert }
    Finally: { Save("cat_red_inv.jpg") }
}

Process "cat.jpg": {
    If pixel Is Bright: { apply Brightness(0.5) }
    Finally: { Save("cat_dim.jpg") }
}

// Чейнинг: несколько модификаторов подряд
Process "photo.jpg": {
    If pixel Is Red: { apply Invert, Blur(3), Brightness(1.2) }
    Finally: { Save("chained_reds.jpg") }
}

Process "photo.jpg": {
    If pixel Is Bright: { apply Invert, Vignette }
    Otherwise: { apply Grayscale, Blur(5) }
    Finally: { Save("chained_full.jpg") }
}

// Предикат Color(Color c): пиксель близок к заданному цвету
Process "photo.jpg": {
    If pixel Is Color({R:255, G:0, B:0}): { apply Invert }
    Finally: { Save("red_to_invert.jpg") }
}

// Count() — считаем красные пиксели через функцию
Image cat = Load("cat.jpg")
Integer reds = Count(cat, Red)
Print("Красных пикселей: " + reds)

// Загрузка изображения: переменная или путь прямо в потоке
Image logo = Load("logo.jpg")
Process logo: {
    If pixel Is Red: { apply Invert }
    Finally: { Save("logo_out.jpg") }
}

Process "logo.jpg": {
    If pixel Is Bright: { apply Brightness(0.7) }
    Finally: { Save("logo_dim.jpg") }
}

// Отладка в середине ветки: Print не меняет пиксель, дальше работает apply
Process "photo.jpg": {
    If pixel Is Red: {
        Print("red at " + x + "," + y)
        apply Invert
    }
    Finally: { Save("debug_reds.jpg") }
}
```

#### Сниппеты мульти-ветвления

**Бинаризация (один проход вместо двух):**
```
Process "scan.jpg": {
    If pixel Is Dark: { apply Color(0) }
    Otherwise: { apply Color(255) }
    Finally: { Save("bw_scan.jpg") }
}
```

**Цветовое кодирование по яркости:**
```
Process "heatmap.jpg": {
    If pixel Is Dark: { apply Color(0, 0, 255) }
    If pixel Is Bright: { apply Color(255, 0, 0) }
    Otherwise: { apply Color(0, 255, 0) }
    Finally: { Save("color_coded.jpg") }
}
```

**Поиск дефекта с `Print()` и `Stop`:**
```
// Finally — один раз в конце; при Stop не выполняется
Process "microchip.jpg": {
    If pixel Is Red: {
        Print("Defect found at: " + x + "," + y)
        Stop
    }
    Finally: { Print("No defects found") }
}
```

**Ветвление + чейнинг:**
```
Process "art.jpg": {
    If pixel Is Red:  { apply Invert, Brightness(1.2) }
    If pixel Is Blue: { apply Brightness(1.2) }
    Finally:          { apply Vignette, Save("processed.jpg") }
}
```

#### Сниппеты мульти-изображений

Методы мульти-изображений можно вызывать как самостоятельно, так и внутри потока.

```
Image overlay = Load("object.png")
Image base = Load("background.jpg")

// Самостоятельный вызов — первый аргумент Image
Image blended = Blend(base, overlay, Do On Each: { Return (src * 0.7) + (over * 0.3) })
Save(blended, "blended.jpg")

// Разностная карта
Image frame1 = Load("frame1.jpg")
Image frame2 = Load("frame2.jpg")
Image diff = Subtract(frame1, frame2, Do On Each: { Return src - over })
Save(diff, "difference.jpg")

// Селективное наложение через поток — Image неявен
Process base: {
    If pixel Is Bright: { apply Blend(overlay, Do On Each: { Return (src * 0.7) + (over * 0.3) }) }
    Finally: { Save("blended_selective.jpg") }
}
```

#### Сниппеты селективных операций

**Селективное размытие (размыть всё, кроме красных):**
```
// Отрицание вместо связки Nothing + Otherwise
Process "photo.jpg": {
    If Not pixel Is Red: { apply Blur(3) }
    Finally: { Save("selective_blur.jpg") }
}
```

**Оператор Собеля (карта краёв для тёмных участков):**
```
Process "objects.jpg": {
    If Not pixel Is Bright: { apply Sobel }
    Finally: { Save("edges_dark.jpg") }
}
```

**Селективный чейнинг:**
```
Process "portrait.jpg": {
    If pixel Is Red:    { apply Invert, Blur(5), Vignette }
    If pixel Is Bright: { apply Brightness(1.2), Color(255, 255, 255) }
    Otherwise:          { apply Grayscale }
    Finally:            { apply Brightness(0.8), Save("portrait_processed.jpg") }
}
```

## 4. Примеры работы компилятора

```
// --- Подпрограммы объявляются в начале программы ---

// --- Основная программа ---

Function Void main(): {
    // Инициализация переменных всех типов
    Image src = Load("photo.jpg")
    Float k = 1.2

    Print("Start processing...")

    // Потоковая обработка с мульти-ветвлением (ветки выполняются
    // последовательно; третья — ветка Otherwise для несовпавших)
    Process src: {
        If pixel Is Red: { apply Invert }
        If R > 200 Or G > 200 Or B > 200: { apply Brightness(k) }
        Otherwise: { apply Grayscale }
        Finally: { Save("output_chain.jpg") }
    }

    // switch-case
    Switch k: {
        Case 1.0: { Print("Коэффициент единичный") }
        Otherwise: { Print("Нестандартный коэффициент: " + k) }
    }

    // Цикл Until
    Integer i = 0
    Until i == 3: {
        Print("Processing step " + i)
        i = i + 1
    }

    Print("Done")
}
```
